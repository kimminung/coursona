# 코르소나(Coursona) UI/UX 디자인 요청 프롬프트

> 이 파일의 아래 내용을 디자인 AI 에게 그대로 붙여 넣고, `Docs/TechPRD.md`(v0.2) 를 함께 첨부한다.
> 작성일 2026-10-05.

---

당신은 Apple 플랫폼(iOS 26 · iPadOS 26 · macOS 26) 앱의 **UX 리드 겸 프로덕트 디자이너**입니다. 첨부한 테크PRD(`TechPRD.md` v0.2)를 근거로 **코르소나(Coursona)** 앱의 **UI/UX 디자인 PRD** 를 작성하세요. 테크PRD 가 "무엇이 기술적으로 가능한가" 를 정했고, 당신은 "사용자가 그것을 어떻게 경험하는가" 를 정합니다. 테크PRD 에 없는 기능을 만들지 말고, 테크PRD 가 못 한다고 한 것을 약속하지 마세요.

## 1. 제품 한 줄

코르소나 = "콜슨이 만든 페르소나". **Vision Pro 의 페르소나처럼**, 내 촬영본으로 만든 흉상이 내 표정·고개·말을 따라 움직이는 경험을 **iPhone·iPad·Mac 에서** 온디바이스로 제공하는 앱입니다. 사진은 서버로 가지 않습니다.

## 2. 테크PRD 읽는 법 (반드시 이 순서로)

1. **§13 "UX 에 넘기는 기능 목록"** — 디자인 범위의 전부입니다. 8개 항목 밖은 설계하지 마세요.
2. **§5 사용자 흐름**, **§6.3 캡처(등급 A/B/C 표)**, **§6.8 라이브 구동** — 화면 상태와 문구의 근거.
3. **§14 미결 사항 Q1–Q10** — 답이 없으면 표의 **기본값**을 채택하고, 디자인 PRD 첫 장에 "채택한 가정" 으로 명시하세요.
4. **§4 비목표**, **§10 위험** — 하면 안 되는 것과 UI 로 완화해야 하는 것.
5. 나머지 절(피팅 수식·파일 포맷·모듈)은 읽지 않아도 됩니다. 궁금하면 참고만 하세요.

## 3. 디자인이 반드시 지켜야 할 기술 사실

- **입력 등급 3가지**: A = Face ID(TrueDepth) iPhone/iPad, B = 일반 카메라(현존 Mac 전부, Face ID 없는 iPhone/iPad), C = 사진 1장. 앱은 어떤 기기도 **막지 않고 등급만 바꿉니다**. B·C 는 "치수 추정"(머리 크기를 모름) 이며, 나중에 Face ID 기기로 다시 찍으면 같은 항목으로 **업그레이드 병합**됩니다.
- **캡처 컷**: A 는 필수 5(정면·왼쪽·오른쪽·위·미소) + 선택 2(눈 감기·입 벌림). B 도 5+2. C 는 정면 1장. 각 컷은 각도 허용 범위(대략 좌우 ±14°·상하 ±12°) 안에서 **0.5 초 유지하면 자동 촬영**, 잠깐 흔들려도 0.35 초 유예. 선택 컷은 건너뛸 수 있고 건너뛰면 "눈·입 정밀도 기본" 입니다. 거울 미리보기는 **기본 꺼짐**(초상 사용자 피드백: 안내의 좌/우와 화면이 반대라 헷갈림).
- **빌드 4단계**: 피팅 → 얼굴면 → 텍스처 → 입체감(스플랫). 예상 시간 A 90 초(iPhone 15 Pro), B 60 초(Mac), C 30 초. 취소 가능.
- **얼굴 표현**: 눈알·치아 같은 **별도 물체가 없습니다**. 눈은 눈꺼풀 + 사진의 눈(시선은 텍스처 이동), 입은 입술 + 입 안쪽 포켓. 그래서 "뚫림" 은 없고, 품질 배지는 **자기교차 0 / N** 입니다.
- **투명 흉상**: 얼굴면만 불투명하게 보이고 머리·목·어깨는 **입체감 스플랫**으로만 보입니다. 시뮬레이터·저사양에서는 스플랫 대신 **옅은 고스트 메시**로 폴백되며 UI 에 "입체감: 기본" 으로 표시합니다. 디버그용 고스트 토글이 있습니다.
- **라이브 구동(거울)**: iPhone/iPad 는 ARKit 52 표정, Mac 은 카메라 영상에서 12가지 표정(입 벌림·미소·오므림·깜빡임·눈썹·시선) + 고개 자세 + 마이크 입모양. Mac 은 시작 후 **2 초 중립 캘리브레이션**이 필요합니다. 지연 목표 120 ms.
- **품질 카드 필드**: 등급(A/B/C), 패치 RMS(mm), 자기교차 수, 치수 알림(B·C), 관측 비율(%), 빌드 시간, 그리고 온디바이스 모델이 쓴 **한 줄 설명**(실패 시 고정 문구). 재촬영 유도는 **어느 컷이 문제인지** 를 가리킵니다.
- **저장·전송**: 패키지 `.coursona`(초상 `.chosang` 도 열림), 캡처 동봉 토글(기본 ON), 기기 간 전송은 **같은 Wi-Fi 에서 6자리 코드**, AirDrop·파일 앱 공유. Mac 은 받기·열기·보기·거울·B 등급 만들기 전부 가능.
- **권한**: 카메라(캡처·거울에서만 요청, Mac 도 동일), 마이크(거울에서만), 로컬 네트워크(전송에서만), 사진(C 등급에서만). 권한 거부 상태의 화면이 전부 필요합니다.
- **범위 밖**(디자인하지 말 것): visionOS, 클립 저작/상황 플레이어, 머리카락·안경 라이브러리 편집 UI(선택 결과만 표시), FaceTime 가상 카메라, 계정·클라우드, 생성형 보정.

## 4. 플랫폼·디자인 체계

- SwiftUI 단일 코드베이스, iPhone(세로), iPad(세로·가로, 가로 거치 캡처 흔함), Mac(창 크기 가변, 사이드바 가능). 같은 화면이 세 폼팩터에서 어떻게 변하는지 명시하세요.
- **iOS 26 / macOS 26 의 Liquid Glass 디자인 체계와 Apple HIG 를 따릅니다.** 시스템 툴바·탭바·시트는 자동으로 Liquid Glass 를 입으므로 **시스템 컴포넌트 우선**, 커스텀 글래스 효과는 3D 뷰포트 위에 떠 있는 컨트롤(촬영 버튼·포즈 토글 등)에만 최소로.
- 3D 뷰포트(흉상)가 주인공입니다. 컨트롤은 뷰포트를 가리지 않게, 어두운 배경 위에서도 읽히게.
- 라이트/다크, Dynamic Type(접근성 크기까지), VoiceOver 라벨, 충분한 명도 대비, 색만으로 상태를 구분하지 않기.
- 언어: **한국어 1차, 영어 2차**. 모든 문구를 KO/EN 표로 제공. 기술 용어는 쓰지 말고 사용자 말로("TrueDepth" 대신 "Face ID 카메라", "스플랫" 대신 "입체감", "자기교차" 대신 "겹침 없음").
- 톤: 차분하고 정직. 등급 B·C 를 열등하게 말하지 말고 "지금 기기로 바로 / Face ID 기기로 더 정밀하게" 로.

## 5. 설계할 화면 (§13 의 8개)

각 화면마다 **목적 · 진입/이탈 · 레이아웃(iPhone/iPad/Mac) · 상태(기본·로딩·빈·오류·권한 거부·폴백) · 컴포넌트 · 문구 KO/EN · 접근성 · 모션** 을 적으세요.

1. **시작·등급 안내** — 세 진입점(Face ID 카메라 / 이 기기 카메라 / 사진 1장)과 기대 품질. 첫 실행 온보딩은 3장 이내.
2. **캡처 가이드** — A/B 공통 골격 + 차이(B: 배경 분리 미리보기·품질 점수 배너), C: 사진 선택 + 적합성 검사. 각도 링(허용 타원), 유지 진행, 자동 촬영 피드백(햅틱·소리), 컷 칩(썸네일), 건너뛰기(선택 컷만), 재촬영, 조도·깊이 경고 배너, 음성 안내 토글(기본 꺼짐).
3. **빌드 진행** — 4단계 진행률, 등급별 예상 시간, 취소, 백그라운드 전환 시 동작.
4. **검수** — 턴테이블, 겹침 배지, 포즈 토글(중립·미소·눈 감기·입 벌림·시선), 투명도/입체감 토글, 품질 카드, 재촬영 유도. 실패·경고 상태 포함.
5. **거울(라이브)** — 카메라 미리보기(선택) + 흉상, 구동 소스 표시, Mac 캘리브레이션 2 초, 마이크 꺼짐 상태, 가려짐(마스크) 상태.
6. **저장·보내기** — 이름, 캡처 동봉 토글, 저장 완료, 다른 기기로 보내기(기기 목록·6자리 코드·진행률·실패 재시도), 공유 시트.
7. **라이브러리·병합** — 목록(썸네일·날짜·기기·등급 배지), 이름 변경·삭제(확인)·재빌드, 업그레이드 흐름("Face ID 기기에서 정밀하게 다시 만들기" → 병합 결과 안내, A → B 덮어쓰기 경고).
8. **Mac 특화** — 받기 화면(코드 표시·수신 진행), 열기(.coursona/.chosang, 템플릿 불일치 안내), 창 레이아웃(사이드바 = 라이브러리, 본문 = 뷰포트, 인스펙터 = 품질/설정), 선택 기능 내보내기(USDZ/PLY) 는 메뉴 항목으로만.

## 6. 산출물 형식

하나의 Markdown 문서 **`UXPRD.md`** 로 작성하고, 아래 순서를 지키세요.

1. 채택한 가정(§14 기본값 포함)과 테크PRD 에 되묻는 질문 목록(있다면, 최대 10개).
2. 디자인 원칙 5개 이내.
3. 정보 구조(IA) 와 내비게이션 모델 — iPhone(탭/스택), iPad, Mac(사이드바·인스펙터) 각각.
4. 핵심 사용자 흐름 다이어그램(텍스트 또는 Mermaid): A 처음 만들기, B(Mac) 처음 만들기, C 사진 1장, 업그레이드 병합, iPhone → Mac 전송.
5. 화면별 스펙(§5 의 8개). 와이어프레임은 **ASCII 또는 상세 텍스트 레이아웃**으로, 요소마다 번호를 붙여 상태표와 연결.
6. 컴포넌트 목록(재사용 단위): 각도 링, 컷 칩, 진행 4단계, 품질 카드, 겹침 배지, 포즈 토글, 등급 배지, 코드 입력 등 — 시스템 컴포넌트로 되는 것은 그 이름을 적고, 커스텀은 이유를 적기.
7. 문구 표 KO/EN(모든 버튼·배너·오류·권한 문구·빈 상태). 권한 사용 설명 문구(카메라·마이크·로컬 네트워크·사진) 포함.
8. 모션·햅틱·사운드 가이드(자동 촬영, 빌드 완료, 전송 완료, 오류).
9. 접근성 체크리스트(Dynamic Type, VoiceOver 순서·라벨, 대비, 색 비의존, 모션 줄이기 대응).
10. 빈 상태·오류·엣지 케이스 목록(카메라 없음, 권한 거부, 얼굴 2명, 마스크·안경 반사, 어두움, 저장 공간 부족, 전송 코드 틀림, 템플릿 불일치, 시뮬레이터/폴백).
11. 수용 기준: 각 화면이 "완료" 로 판정되는 조건(테크PRD §9 의 실기기 체크리스트와 연결).

## 7. 하지 말 것

- 테크PRD §13 밖의 기능·화면·설정 추가.
- 눈알·치아·입안 같은 분리 물체를 전제한 UI(예: "눈알 색 바꾸기").
- B·C 등급에서 정확한 치수나 옆모습 정확도를 암시하는 문구.
- 서버·계정·클라우드·AI 생성 보정을 암시하는 UI.
- 기술 용어 노출(TrueDepth, ARKit, RMS, 스플랫, 자기교차, RBF). 품질 카드의 숫자는 "자세히" 를 눌렀을 때만.
- 커스텀 글래스·블러 남용, 뷰포트를 가리는 큰 패널.

## 8. 답하는 방식

- 테크PRD 와 충돌하면 **테크PRD 가 우선**이고, 충돌 지점을 "되묻는 질문" 에 적으세요.
- 결정이 필요한데 근거가 없으면 **합리적 기본값을 고르고 가정으로 표시**하세요. 작업을 멈추고 묻지 마세요.
- 한국어로 작성하되 문구 표는 KO/EN 둘 다.
- 분량보다 **상태 누락 없음**이 중요합니다. 화면마다 상태표가 비어 있으면 미완성입니다.
