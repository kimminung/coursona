# Coursona 디자인 PRD — 비전프로 Persona 재현 에셋 (Hair · Shoulders · Eyes/Mouth)

Oct 7, 2026 · @Coulson

## 개요와 목표

이번 라운드는 Bust 본체를 건드리지 않고, Persona 룩에서 비어 있는 세 부분(머리카락, 상의, 눈알·입 안)을 TemplateValidator 계약을 통과하는 라이브러리 에셋으로 채운다.

- **대상**: coursona — 비전프로 Persona 같은 실사형 아바타를 아이폰에서 재현하는 앱. Chosang의 흉상 템플릿·라이브러리 제작 방식과 Soban의 ARKit 52 블렌드셰이프 구동 방식을 가져온다.
- **산출물**: Hair\_long\_wave, Shoulders\_shirt, Eye\_L·Eye\_R·Mouth\_Inner 실메시, 다시 내보낸 Template.usdz(및 EyesMouth.usdz), library.json, Template/textures/\*.png.
- **성공 기준**: TemplateValidator 통과, Bust와의 관통 0건, 다섯 개 입 셰이프키를 Bust와 같은 값으로 구동했을 때 입 안이 입술과 같이 움직임, 첨부 레퍼런스와 나란히 볼 때 실루엣(머리 볼륨, 카라, 가슴 아래 페이드)이 같은 인상.
- **범위 밖**: Bust 메시·리그·ARKit 1220점 패치 수정, 피부 셰이딩 개선, 실시간 헤어 시뮬레이션.

## 레퍼런스 분석

첨부 이미지(WWDC25 visionOS 26 Persona)의 인상은 얼굴보다 **실루엣 세 가지** — 볼륨 있는 긴 머리, 짙은 카라 셔츠, 가슴 아래로 사라지는 몸통 — 가 만든다. 이번 에셋은 이 세 가지를 우선한다.

| 요소 | 레퍼런스에서 보이는 것 | coursona 반영 |
| --- | --- | --- |
| 머리카락 | 진갈색 + 밝은 하이라이트, 가운데 가르마, 볼 높이부터 시작하는 큰 웨이브, 옆 볼륨, 잔머리로 경계가 부드러움 | Hair\_long\_wave: 그레이스케일 + 알파 카드, 앱 틴트로 색. 끝은 어깨 위 1.5 cm에서 멈춤(v1, 아래 "결정" 참고) |
| 상의 | 짙은 네이비 카라 셔츠, 뾰족한 카라, 단추를 끝까지 잠근 형태, 주름 거의 없음 | Shoulders\_shirt: 단색 네이비 PBR, 칼라 스탠드 + 접힌 칼라 + 앞 포인트 |
| 몸통 경계 | 가슴 중간부터 아래로 투명해지는 그라데이션, 어깨 바깥도 살짝 흐림 | 메시는 Bust 하단 절단면까지 덮고, 페이드는 앱 셰이더에서 처리(UV v = 높이) |
| 눈 | 정면 응시, 또렷한 캐치라이트, 홍채 결 | Eye\_L/R: 공막·홍채·동공 3 슬롯, 홍채·동공은 앞쪽 투영 UV로 텍스처 교체 가능 |
| 입 | 미소 때 윗니가 또렷이 보임 | Mouth\_Inner: 위·아래 치아, 잇몸, 혀, 입안 주머니 + 턱 셰이프키 5개 |
| 조명 | 방 조명과 같은 따뜻하고 부드러운 빛, 가장자리 미세한 빛 번짐 | 앱 쪽 IBL/조명 매칭(이번 에셋 범위 밖, 머티리얼은 PBR 값만 맞춤) |

**결정 — 머리 길이**: 레퍼런스는 머리가 어깨를 넘어 가슴까지 내려오지만, v1은 요청대로 어깨 위 1.5 cm에서 끝낸다. 머리카락은 Head 뼈에 강체 고정이라, 어깨를 덮으면 고개를 숙일 때 셔츠·어깨를 뚫는다. 어깨를 덮는 앞머리는 v2에서 Neck 스킨 또는 2차 모션으로 다룬다.

## 에셋 계약

모든 라이브러리 에셋은 이름·고정 방식·library.json 항목, 이 세 가지가 TemplateValidator와 일치해야 통과한다. 좌표는 블렌더 Z-up, 얼굴 −Y, 피사체 왼쪽 +X, 미터 단위이고, USD로 나가면 USD (x, y, z) = 블렌더 (x, z, −y)다.

| kind | 오브젝트 | 고정 방식 | bone | 스킨 그룹 | tintable | 텍스처·머티리얼 |
| --- | --- | --- | --- | --- | --- | --- |
| hair | Hair\_long\_wave | Head 뼈 강체 고정. 버텍스 그룹·Armature 모디파이어 없음, 오리진 = Head 뼈 머리 위치 | Head | 없음 | true | 머티리얼 1개, base = 회색 RGB + 알파 PNG |
| shoulders | Shoulders\_shirt | Armature 스킨. Bust의 Root·Neck 가중치를 복사한 뒤 두 그룹 합을 1로 정규화 | Root | Root, Neck | false | 단색 네이비 PBR, 텍스처 없음 |
| eye | Eye\_L, Eye\_R | 같은 이름의 눈 뼈에 강체 고정. 오리진 = 눈 뼈 머리 = template.json 눈알 중심(0.5 mm 이내) | Eye\_L / Eye\_R | 없음 | — | 슬롯 순서 고정: 공막 → 홍채 → 동공 |
| mouth | Mouth\_Inner | Head 뼈 강체 고정 + 셰이프키 5개. 계약 스켈레톤에 Mouth\_Inner 뼈가 없으므로 새 뼈를 만들지 않는다 | Head | 없음 | — | 치아·잇몸·혀·입안 |

**library.json 항목** — 필드는 `name`, `kind`, `bone`, `tintable`, `vertexCount`, `faceCount`, `materials`, 그리고 kind에 따라 `textures` 또는 `skinGroups`.

- `vertexCount`·`faceCount` 는 블렌더 메시 수(정점·면) 그대로다. 내보낼 때 삼각화하지 않으므로 USD의 points·faceVertexCounts 수와 같다.
- `materials` 는 머티리얼 슬롯 이름을 슬롯 순서대로 적는다.
- 같은 값을 오브젝트 커스텀 속성(`coursona_kind`·`coursona_bone`·`coursona_tint`·`coursona_textures`·`coursona_skin_groups`)에도 넣어, USD userProperties로도 읽히게 한다.

**내보내기 규칙**

- export\_coursona.py, Apply Modifiers OFF. 따라서 모든 형태는 메시에 구워져 있어야 하고, 남는 모디파이어는 셔츠의 Armature 하나뿐이다.
- 텍스처는 Template/textures/에 sRGB PNG, 스트레이트 알파, 2의 거듭제곱 크기로 둔다.
- 컬렉션은 이미 있으면 재사용한다. 새로 만들면 블렌더가 `Library_Hair.001` 처럼 이름을 바꿔 계약이 깨진다.

* **투명 기본값**: 모든 에셋 머티리얼은 무채색 연회색 + Alpha 상수 0.10으로 내보낸다(USD `opacity` 0.1, 색·텍스처 연결 없음). 머리 알파 텍스처는 BSDF에 연결하지 않고 실루엣 마스크로만 전달한다(§룩·렌더링 원칙).

**TemplateValidator.swift(2차 계약, ChosangValidate)로 확인한 것**

- **이름**: `^(Hair|Glasses|Beard|Shoulders)_[a-z0-9_]+$` 규칙을 따라야 한다. 헤어 계약 12종에 `long_wave` 가, 필수 라이브러리에 `Shoulders_shirt` 가 들어 있다. 그래서 두 오브젝트는 초상 .blend에 이미 있을 가능성이 높고, 스크립트는 .blend 사본을 저장한 뒤 같은 이름으로 교체한다.
- **kind별 검사**: shoulders는 skinGroups에 Root·Neck이 없으면 경고, hair는 `textures.base` 가 없으면 경고, 참조 텍스처가 Template/textures에 없으면 오류다.
- **스켈레톤**: Root > Spine > Neck > Head > {Eye\_L, Eye\_R} 여섯 개뿐이다. 눈 뼈 머리는 눈알 중심과 0.5 mm 이내, 눈 간격은 64 ± 3 mm, 눈 높이는 0.44 ± 0.01 m다.
- **Mouth\_Inner 셰이프키 5개**: template.json의 `mouthInnerShapes` 로 검사하며 빠지면 오류다. coursona T-003은 이 메타를 무시하도록 가드했으므로 함께 풀어야 한다.
- **내보내기**: CLI 스크립트로 실행한다. `--no-usdz` 는 쓰지 않고, Apply Modifiers는 끈다.
- **검사하지 않는 것**: 머리카락을 스킨으로 붙였는지 강체로 붙였는지는 보지 않는다. 강체 규칙은 앱의 부착 방식이 정한다(§리스크).
- 이 파일은 초상 검증기다. coursona 포팅본의 기준이 다르면 그쪽을 따른다.

## 에셋 스펙 1 — Hair\_long\_wave

두피 캡 1장 위에 웨이브 카드 366장을 5층(inner · mid · outer + 얼굴을 감싸는 frame + 헤어라인 잔머리 baby)으로 얹는다. Head 뼈에 강체로 고정하고, 회색 + 알파 텍스처 1장을 앱에서 틴트한다(보조 마스크 1장). 대리 흉상 기준 정점은 약 2.3만, 면은 1.5만이다.

| 항목 | 값 |
| --- | --- |
| 구조 | 캡(Scalp 그룹 면을 1.5 mm 띄움, 불투명) + 카드 5층(inner 84 · mid 112 · outer 88 · frame 12 · baby 70장) |
| 층 높이 | 4.0 / 8.5 / 13.5 mm(frame 5.0, baby 2.2). 정수리 근처는 0.5배, 길이 3→14 cm 구간에서 +11 mm 볼륨 |
| 가르마 | 정중선에서 피사체 왼쪽으로 5 mm. 앞·위쪽은 가르마 ±4.5 mm에 뿌리를 두지 않는다. 뒤는 갈라지지 않게 곧게 빗는다 |
| 웨이브 | 길이 9 cm(볼 높이)부터 시작. 진폭 11 mm, 파장 9.5 cm ±15%, 같은 덩어리는 위상을 공유 |
| 길이 | 최대 36 cm(frame 30 cm, baby 5.5 cm). 바로 아래 표면(어깨·등·칼라)에서 1.8 cm 위에서 멈추고, 머리 중심에서 옆으로 12.5 cm 이상 나가지 않는다 |
| 얼굴 회피 | ARKit 패치의 높이별 반폭 + 4 mm 바깥으로만 지나간다 |
| 카드 | 20구간 × 3열(baby는 6구간), 뿌리 폭 7–24 mm, 끝은 62%로 가늘어짐. mid·outer는 길이를 따라 최대 0.18·0.25 rad 비틀리고 폭이 ±5% 변한다 |
| 간격 기준 | 레스트에서 캡 ≥ 0.9 mm, 카드 ≥ 1.4 mm. 포즈 7종 관통 0, Bust와 삼각형 교차 0 |
| 텍스처 | `T_Hair_LongWave_base.png` 2048², 카드 6칸 + 캡 칸. 뿌리 −30% 어둡게, 끝으로 갈수록 +12% 발레아주, 12%는 밝은 하이라이트 가닥, 잔머리 포함. 보조 `T_Hair_LongWave_mask.png`: R 뿌리→끝, G 가닥 id, B 하이라이트 |
| 머티리얼 | `M_Hair_LongWave`: Base Color ← base RGB, Alpha ← base A, Roughness 0.45, 백페이스 컬링 끔 |
| 틴트 | 평균 회색이 0.63이므로 앱 틴트 = 목표색 ÷ 0.63. 진갈색 #4A3325 → 틴트 #75513B |
| 부착 | 기본은 Head 뼈 부모(계약). 대안: SkelRoot 밖이 필요하면 Child Of, 앱의 강체 부착이 준비되기 전에는 Head 100% 스킨 |

셔츠가 이미 있으면 머리는 Bust와 셔츠를 합친 표면을 기준으로 간격을 잡는다. 그래서 실행 순서는 셔츠 다음에 머리다.

## 에셋 스펙 2 — Shoulders\_shirt

Bust의 Shoulders 영역을 복제해 3.5 mm 띄운 몸판에, 목둘레를 따라 칼라(스탠드 · 접힘 · 리프)를 이어 붙인다. 몸판은 원본 정점의 Root·Neck 가중치를 그대로 받으므로, 목을 돌려도 피부와 같은 비율로 따라간다.

| 항목 | 값 |
| --- | --- |
| 몸판 | Shoulders 그룹(가중치 > 0.5) 면 복제 → 법선 방향 3.5 mm. 경계를 고정한 라플라시안 6회로 쇄골 오목을 천처럼 덮고, 최소 2.8 mm 보장 |
| 절단면 | 아래·팔 절단 고리를 피부 위 0.8 mm까지 안으로 접어 틈을 닫는다 |
| 칼라 스탠드 | 목둘레 고리에서 목을 따라 앞 18 mm → 뒤 24 mm, 목에서 4.5 → 5.5 mm, 4줄. 둘레 해상도는 목둘레 정점의 2배 |
| 접힘 | 스탠드 위끝에서 2.5 mm 바깥, 1.2 mm 위 |
| 리프 | 접힘 아래 피부를 정해진 길이만큼 걸어 내려간다: 뒤 30 mm, 앞 포인트(정면에서 ±0.40 rad) 60 mm, 정중앙 V 노치 14 mm. 피부에서 8.5 → 12.5 mm, 6줄 |
| 스킨 | 몸판·접기 정점은 원본 Bust 정점의 Root·Neck 값, 칼라 정점은 가장 가까운 Bust 면에서 보간. 두 그룹 합 1(둘 다 0이면 Root 1) |
| 모디파이어 | Armature 하나. 볼륨 보존 옵션은 Bust 설정을 따른다 |
| 머티리얼 | `M_Shirt_Navy`: Base Color #1E2A44(sRGB), Roughness 0.82, Specular 0.30. Sheen 0.25는 블렌더 미리보기 전용 |
| UV | u = 둘레 각도(정면 0.5), v = 높이(0 아래 끝 → 1 칼라 위). 앱 하단 페이드가 v를 쓴다 |
| 간격 기준 | 레스트에서 몸판 ≥ 1.8 mm, 칼라 ≥ 2.8 mm. 포즈 7종(좌우 30°, 숙임 25°, 젖힘 20°, 기울임 ±15°, 복합)에서 관통 0 |

대리 흉상 시험 결과 칼라 정점은 1,232개, 목과의 최소 간격 3.7 mm, 칼라 위끝 z 0.298 m, 앞 포인트 끝 z 0.236 m였다. 처음 시험에서는 리프를 광선으로 놓았는데, 어깨 경사에서 멀리 튀어 망토처럼 퍼져서 표면 걷기 방식으로 바꿨다.

**v1.1 디테일**

- 앞 중심 플래킷: 3열 띠, 몸판 위 1.6 mm, 가운데가 0.4 mm 더 솟음

## 에셋 스펙 3 — Eye\_L / Eye\_R / Mouth\_Inner

작업 3의 원인은 "메시가 없다"보다 "스킨 메시라서 이름으로 못 찾는다"일 가능성이 높다. 그래서 순서를 진단 → 기존 메시 재사용과 강체 전환 → 없을 때만 생성으로 잡는다.

초상 .blend(10/4 README 기준)에는 Eye\_L/R(반지름 12 mm, 머티리얼 3개)과 Mouth\_Inner(치아·잇몸·혀·입안, 셰이프키 5개, Bust 드라이버)가 이미 뼈 100% 스킨으로 있다. 스킨 메시는 USD에서 SkelRoot 아래 스킨 메시로 나가고, RealityKit이 이를 스켈레톤 엔티티 하나로 합친다는 것이 가설이다. inspect\_usdz.py가 이를 확인한다.

1. **진단**: 세 오브젝트의 존재, 타입, 부모, 스킨 여부, 머티리얼, 셰이프키, 컬렉션, 렌더 표시 여부를 보고서에 남긴다.
2. **눈 중심**: 메시 구 중심을 최소제곱으로 구해 눈 뼈 머리와 비교한다. 0.5 mm 이내면 그대로 두고, 3 mm 이내면 메시를 뼈 머리로 옮긴다. 그보다 크면 옮기지 않고 계약 문제로 보고한다.
3. **강체 전환**: 단일 뼈 100% 스킨이면 Armature 모디파이어와 버텍스 그룹을 지운다. 셰이프키를 포함한 모든 키 좌표를 같이 옮긴다. 여러 뼈에 스킨돼 있으면 건드리지 않고 경고만 한다.
4. **눈 슬롯 순서**: 이름이 아니라 기하로 판정한다. 앞축(−Y)에서 각도가 가장 작은 슬롯이 동공, 중간이 홍채, 가장 큰 슬롯이 공막이다. 이를 공막 → 홍채 → 동공 순서로 다시 놓는다.
5. **입 셰이프키**: 다섯 개 중 없는 것만 만든다. 턱 키 4개는 Bust의 같은 키에서 턱끝 정점(ARKit 패치 중 입 중심 12 mm 아래, |x| < 35 mm)을 Kabsch로 강체 맞춤해 아래턱 부분에 적용한다. tongueOut은 혀 앞쪽을 16 mm 내민다. 각 키는 Bust의 같은 이름 키 값을 드라이버로 따른다. 드라이버는 블렌더 미리보기용이고 USD에는 나가지 않는다.
6. **부착**: 눈은 같은 이름의 눈 뼈, 입은 Head 뼈에 강체로 붙인다. 오리진은 눈알 중심, 입은 입 루프 36정점 평균이다.

## 룩·렌더링

에셋에는 형태와 기본 머티리얼까지만 담는다. Persona 인상을 결정하는 나머지(알파, 틴트, 하단 페이드, 목 표시, 시선)는 앱이 USDZ를 읽은 직후 머티리얼을 조정해 만든다. 블렌더 USD 내보내기가 알파 클립이나 양면 설정을 그대로 옮겨 준다고 보장할 수 없기 때문이다.

**원칙 — 블렌더 에셋은 투명한 틀이다.** 네 에셋 모두 색을 뺀 무채색 연회색(0.8)에 기본 불투명도(Alpha) 0.10, 즉 90% 투명으로 나간다(`asset_opacity=0`.10, colorless=True). 블렌더 에셋은 형태·배치·실루엣·깊이만 제공하고, 보이는 색은 Xcode가 사진 기반 페르소나(투영 텍스처·스플랫)로 입힌다. 그래야 레퍼런스처럼 "사진에서 나온 사람"만 보이고, 에셋 고유의 칠한 색이 섞이지 않는다.

살색 부위도 같다. Bust의 Skin 머티리얼을 같은 무채색 10%로 바꾼다(`skin_carrier=True`, 머티리얼 값만 — 메시·리그·그룹·UV·셰이프키는 그대로). 얼굴 윤곽은 앱이 트루뎁스 정점으로 만들므로, 미리보기용 대리 두상은 둥근 타원체 하나로 두고(이마·턱·코·입술 볼륨 없음) 남녀 차이는 머리폭·목 둘레·어깨폭만 남긴다.

| 단계 | 앱에서 할 일 | 에셋이 주는 것 |
| --- | --- | --- |
| 1 색 입히기 | 머리: 사진 머리색 틴트(T-704) 또는 두피 스플랫 색. 셔츠: 어깨 영역 사진 평균색. 눈·입안: 정면·입 벌림 컷 투영(T-502), 없으면 블렌더 텍스처 폴백 | 회색 base 텍스처, 홍채·공막·치아 폴백 텍스처 |
| 2 실루엣 | 머리 카드 opacity 텍스처 = `textures.base` 의 알파 채널(커스텀 속성 `coursona_silhouette`) | 알파 마스크, 메시 윤곽 |
| 3 유령 합성 | 페르소나 엔티티만 오프스크린 렌더 → 실루엣 마스크 가장자리 8–14 px 가우시안 블러 → 전체 불투명도 0.85 → 하단 페이드(UV v 0 → 0.35) → 카메라/배경 위 합성 | 깊이·마스크 |

블렌더 뷰포트에서는 유령 미리보기(표시 알파 0.15)로 보이고, 형태만 확인하려면 `run_all.main(asset_opacity=1.0)` 으로 잠시 불투명하게 만들 수 있다. 아래 표의 머티리얼 값(roughness·clearcoat·opacityThreshold)은 앱이 opacity를 올린 뒤 적용하는 값이다.

| 요소 | 앱에서 할 일 | 이유 |
| --- | --- | --- |
| 머리 알파 | `opacityThreshold` 0.45(알파 컷), `faceCulling = .none` | 반투명 블렌딩은 카드 정렬 문제가 생긴다. 카드는 양면으로 보여야 한다 |
| 머리 색 | baseColor 틴트 = 목표색 ÷ 0.64 | 회색 텍스처 평균이 0.64. 머리 선택 유지(T-704)와 사진 머리색에 연결 |
| 하단 페이드 | 셔츠 UV v 0 → 0.35 구간에서 알파 0 → 1. iOS·macOS는 CustomMaterial 표면 셰이더 | 가슴 아래로 사라지는 몸통이 레퍼런스의 핵심 실루엣이다 |
| 아이폰 목·귀 | 라이브러리 헤어·셔츠를 쓸 때 Bust "나머지" 파트를 불투명(1.0)으로 표시 | 지금 기본값은 나머지 파트 opacity 0(T-103, Q2)이라, 그대로 두면 머리·셔츠 사이에 목이 비어 보인다 |
| Mac 스플랫 | 헤어를 쓰면 두피 스플랫을, 셔츠를 쓰면 어깨 스플랫을 끈다 | 스플랫(T-503)과 메시가 같은 자리에서 겹친다 |
| 눈 | 공막 roughness 0.18, 홍채 0.25 + clearcoat 0.6(T-604 값 재사용), 동공 0.10. 눈알이 있으면 시선은 엔티티 회전으로 처리 | 캡 UV 이동(T-604)은 눈알이 없는 템플릿용 폴백으로 남긴다 |
| 입안 | 치아 roughness 0.35, 입안 주머니는 거의 검정 | 입을 벌려도 머리 내부가 보이지 않게 |
| 조명 | ImageBasedLight + 따뜻한 키 라이트 | 레퍼런스의 실내광 인상. 이번 에셋 범위 밖 |

텍스처는 다섯 장이다: 헤어 base·mask, 눈 홍채·공막, 치아. 눈과 치아 텍스처는 블렌더 머티리얼의 Base Color에 이미 연결되어 USDZ에 같이 들어가므로, 앱은 눈의 roughness·clearcoat 값만 맞추면 된다.

## 리스크와 미결정 사항

가장 큰 리스크는 강체 부착이다. 뼈에 부모로 붙인 메시는 USD로 나가면 조인트를 따라가지 않으므로, 앱에 강체 부착 시스템이 없으면 머리카락과 눈이 고개를 따라 움직이지 않는다.

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 뼈 부모 메시는 USD에서 정적 프림이 된다 | 클립·라이브 고개 회전 때 머리·눈·입안이 제자리에 남는다 | 앱에 RigidAttach 시스템 추가(library.json `bone` 의 조인트 변환을 매 프레임 복사). 그전까지는 헤어만 `SKIN_HEAD` 비상 경로 |
| 강체 메시가 SkelRoot 아래에 놓인다 | RealityKit이 스켈레톤 엔티티에 합쳐 이름으로 못 찾을 수 있다 | inspect\_usdz.py와 `findEntity` 로 확인. 안 잡히면 `attach_mode="CHILD_OF"` 로 다시 실행 |
